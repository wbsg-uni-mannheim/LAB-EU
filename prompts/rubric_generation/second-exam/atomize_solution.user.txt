Rules:
- Infer the output language from the case and solution.
- The atom statements, materiality explanations, equivalents, and alternatives must be in that same language.
- Each atom must be exactly one legal proposition that is independently checkable in an agent answer. Do not bundle several requirements into one atom.
- Cover the material structure of the solution without forcing it into predefined categories.
- Include issues, rules, facts, application/subsumption, conclusions, source grounding, form requirements, counterarguments, and important exclusions only where the task and solution make them material.
- Name the legal basis verbatim in legal_basis where the atom rests on specific provisions (for example "§ 42 Abs. 2 VwGO"). Leave the list empty if none applies.
- Set expectation to "core" if every acceptable answer must contain the point. Set it to "bonus" if the solution itself marks the point as not expected or as optional depth, for example in a Lösungshinweis, a footnote-only discussion, or wording like "Kenntnis kann nicht erwartet werden".
- Legal solutions often flag defensible alternative positions ("a.A. vertretbar", "andere Ansicht", Lösungshinweise, Aufbauhinweise). Record each such alternative in defensible_alternatives on the affected atom: state the alternative position and what a good answer must still contain when taking it. Do not treat these alternatives as errors. Record only alternatives expressly accepted by the supplied solution; never add a possible literature position from your own knowledge.

If the solution uses competing approaches as alternatives, record the chosen reference path and only those alternatives the solution expressly accepts. A criterion must never require an answer to present every available theory unless the solution makes that comparison material.
- If the solution notes that a point may be examined at a different place in the document structure (for example an Aufbauhinweis allowing a point in either admissibility or merits), record that in placement_flexible so later criteria do not require one specific location.
- Keep person and examination-station scope explicit. If the same legal issue is examined for several people, claims, administrative acts, offences, or procedural stages, create separate atoms whenever the required reasoning or result differs. Do not let a proposition about one object silently stand for another.
- Distinguish a legal examination from its result. When the solution supplies a rule, application, or argument, the atom must describe that legal work rather than only the resulting conclusion.
- Prefer legally significant facts over incidental precision. Do not make exact distances, seconds, dates, amounts, or quotations independently mandatory unless the task or solution makes that precision material to the legal conclusion.
- Flag apparent gaps, internal contradictions, or passages that state a conclusion without the supporting legal step in solution_gaps_or_warnings. Do not silently convert a gap in the supplied solution into a mandatory criterion.

- Keep source_refs and solution_refs short; use filenames or section names, not long quotations.
- If the human solution is incomplete, truncated, or internally uncertain, record that in solution_gaps_or_warnings.
